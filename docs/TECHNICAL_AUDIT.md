# Технический аудит L.o.S.A.

Аудит выполнен по ветке `feature/v0.9-authentication-foundation` перед работой над v0.9.1. Это список следующих задач, а не заявление о том, что все функции уже проверены на реальном компьютере.

## Исправляется в v0.9.1

- Состояние установленного клиента терялось при перезапуске интерфейса: React-состояние не восстанавливалось с диска.
- Не было устойчивой отметки о завершённой загрузке библиотек и ресурсов.
- Версии в интерфейсе, `package.json`, Tauri и Cargo расходились.

## Следующие технические задачи

1. **Java Runtime.** Сейчас лаунчер ищет Java в системном `PATH`, но не устанавливает совместимую Java автоматически. Нужно определить безопасный источник дистрибутива, проверять контрольные суммы и выбирать runtime по `javaVersion.majorVersion` из метаданных Mojang.
2. **Правила библиотек.** Текущая фильтрация учитывает в основном имя ОС. Нужно полностью обработать правила Mojang, включая архитектуру, версию ОС и feature flags, прежде чем заявлять поддержку всех версий и загрузчиков.
3. **Игровые ресурсы.** Нужно реализовать legacy layouts для `virtual` и `map_to_resources`, если они присутствуют в asset index, и передавать Minecraft правильный путь к ресурсам.
4. **Журнал запуска.** Сейчас stdout/stderr пишутся в файл, но интерфейс не показывает журнал и не различает успешный запуск процесса и немедленное завершение JVM.
5. **Сессия Microsoft.** Токен хранится только в памяти приложения; после перезапуска пользователь входит заново. До реализации безопасного обновления токенов и хранения сессии это ожидаемое ограничение.
6. **Профили сборок.** Список сборок пока демонстрационный и хранится в React state; его нужно заменить реальными профилями на диске с отдельными версиями, каталогами игры и настройками.
7. **Аккаунт L.o.S.A.** Email/password регистрация пока описана в `docs/ACCOUNT_SYSTEM.md`, но сервер, база данных, подтверждение почты и восстановление доступа ещё не реализованы.
8. **Разделы продукта.** Друзья, моды и серверы пока являются заглушками. Их нужно подключать поэтапно после стабилизации базового запуска.

## Ограничения проверок

- Успешный GitHub Actions подтверждает, что проект собирается в среде Windows CI, но не доказывает, что Minecraft запускается на пользовательском ПК.
- Для подтверждения игрового запуска нужны реальные проверки на Windows с лицензией Minecraft Java и подходящей Java Runtime.
- Microsoft Device Code Flow остаётся официальным способом входа; L.o.S.A. не должна запрашивать пароль Microsoft напрямую.
