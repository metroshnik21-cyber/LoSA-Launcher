# План системы аккаунтов L.o.S.A.

## Текущий этап: локальный Offline-профиль

На этапе разработки и тестирования L.o.S.A. использует локальный Offline-профиль как единственный доступный способ входа. Пользователь задаёт игровой ник; почта, пароль, Azure, Microsoft Entra и Client ID не требуются. Это временное решение для тестирования лаунчера и игры в одиночном режиме или на серверах, разрешающих offline-mode.

Microsoft-авторизация и проверка лицензии отложены до отдельного решения владельца проекта. Не блокировать разработку, сборку и тестирование L.o.S.A. ожиданием Microsoft-настроек.

## Потоки пользователя

1. Регистрация L.o.S.A.: адрес электронной почты, пароль, подтверждение адреса одноразовым кодом или ссылкой.
2. Вход L.o.S.A.: электронная почта и пароль.
3. Восстановление доступа: одноразовая ссылка или код с ограниченным сроком действия.
4. Подключение Minecraft: отдельная кнопка, открывающая официальный сайт Microsoft. Пароль Microsoft вводится только на стороне Microsoft; лаунчер не собирает и не хранит его.
5. Выход и управление сессиями: завершение текущей сессии и отзыв отдельных устройств.

## Локальный Offline-профиль (v0.9.2)

Локальный профиль — отдельный режим запуска без учётной записи Microsoft и без серверной регистрации L.o.S.A. Игрок задаёт ник (3–16 символов: латинские буквы, цифры и подчёркивание); лаунчер формирует стандартный Minecraft Offline UUID и запускает игру с offline/legacy-параметрами. Ник хранится локально на компьютере. Этот профиль не подтверждает владение Minecraft и не предоставляет доступ к Realms или серверам, требующим лицензионную online-mode-аутентификацию. Подключаться можно к одиночной игре и серверам, которые явно разрешают offline-mode. Серверы с online-mode=true продолжают проверять официальную лицензионную авторизацию.

Локальный Offline-профиль не является аккаунтом L.o.S.A.: синхронизация между устройствами, восстановление профиля и серверная идентичность для него не предусмотрены. Microsoft OAuth в текущей версии отключён в пользовательском интерфейсе и не требуется для сборки или запуска Offline-профиля.

## Обязательные требования безопасности

- Пароли L.o.S.A. никогда не хранятся в открытом виде; сервер хранит только стойкие хеши паролей с индивидуальной солью (Argon2id или эквивалент).
- Подтверждение электронной почты обязательно до использования социального функционала и покупок.
- Ограничение частоты попыток входа, регистрации, восстановления пароля и отправки писем.
- Одноразовые токены подтверждения и восстановления хранятся в хешированном виде и имеют короткий срок действия.
- Секреты почтового провайдера, подпись токенов и ключи базы данных находятся только на сервере.
- Токены Microsoft не передаются в систему аккаунтов L.o.S.A. без необходимости и не записываются в журналы.
- Сервер проверяет права и роли; роль Founder/Admin/Moderator нельзя назначить через клиентский интерфейс.
- Все критические действия (изменение почты, пароля, 2FA, роли) требуют повторной проверки сессии.

## Серверная архитектура — следующий этап

Потребуются HTTPS API, база данных пользователей, сервис сессий, почтовый провайдер для писем подтверждения/восстановления и административный аудит. Конкретный хостинг и почтовый провайдер ещё не выбраны; до выбора и настройки этих сервисов настоящую регистрацию нельзя считать реализованной.

## Microsoft OAuth — отложено

Microsoft OAuth не входит в текущий этап и не должен отображаться как обязательная настройка игрока или разработчика. Возвращаться к нему можно только по отдельному решению владельца проекта.

## Текущее состояние

В версии 0.9.2 используется только локальный Offline-профиль. Microsoft-вход, Client ID, Azure и проверка лицензии отложены. Тестирование лаунчера продолжается без них.

Этот документ фиксирует целевую архитектуру. Собственная регистрация L.o.S.A. по электронной почте пока не реализована: для неё ещё не выбраны и не подключены сервер, база данных и почтовый сервис.
