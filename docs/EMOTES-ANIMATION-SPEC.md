# L.o.S.A. Emotes — техническая спецификация первого этапа

Версия спецификации: 1.0  
Версия лаунчера для интеграции: 0.11.4  
Статус: платформенно-независимая основа; игровые адаптеры ещё не реализованы.

## 1. Цель первого этапа

Создать единый каталог и формат описания полноценных анимаций персонажа, который смогут использовать две самостоятельные реализации:

- **Java Edition** — клиентский мод L.o.S.A. Cosmetics для выбранной версии Minecraft и модлоадера.
- **Bedrock Edition** — отдельный набор Resource Pack / Behavior Pack и, если потребуется после прототипа, Script API.

Java и Bedrock не делят игровые файлы и не используют один и тот же исполняемый мод. Они разделяют только стабильные ID эмоций, метаданные, правила воспроизведения и смысл анимаций.

На этом этапе создаётся общий формат данных. Наличие этих данных само по себе ещё не означает, что эмоции уже воспроизводятся внутри Minecraft.

## 2. Первый каталог

| ID | Название | Длительность | Характер |
|---|---|---:|---|
| `losa:greeting` | Приветствие | 1 800 мс | Поднять правую руку и помахать, слегка повернуть корпус и голову |
| `losa:bow` | Поклон | 1 600 мс | Наклонить корпус и голову, руки отвести назад |
| `losa:dance` | Танец | 3 200 мс | Переносить вес с ноги на ногу, двигать руками и корпусом |
| `losa:rest` | Отдых | 4 500 мс | Опуститься в сидячую позу и вернуться в исходное положение |
| `losa:applause` | Аплодисменты | 2 200 мс | Свести руки перед корпусом и выполнить несколько хлопков |
| `losa:facepalm` | Фейспалм | 1 900 мс | Поднести ладонь к лицу, задержать позу и убрать руку |

Все шесть эмоций в первом наборе нециклические. Повторный запуск возможен после окончания текущей эмоции.

## 3. Общий скелет

Канонический набор костей:

- `root` — общий узел персонажа, только визуальное смещение;
- `body` — корпус;
- `head` — голова;
- `left_arm`, `right_arm` — руки;
- `left_leg`, `right_leg` — ноги.

Углы задаются в градусах в локальных осях X/Y/Z. Перемещение задаётся в модельных пикселях, где 16 пикселей соответствуют одному блоку. Ключи указывают абсолютную позу кости на соответствующий момент клипа. Если кость не указана в ключе, для неё сохраняется нейтральная поза текущего клипа.

Адаптер каждой платформы обязан преобразовать этот формат в собственный механизм анимации. Он не должен менять ID или длительность клипа.

## 4. Правила воспроизведения

- Одновременно у игрока может быть активна только одна эмоция.
- Повторное нажатие той же эмоции не создаёт параллельный экземпляр.
- Эмоцию можно отменить вручную.
- Эмоция завершается или отменяется при движении игрока, прыжке, атаке, получении урона, смерти, смене измерения или отключении.
- Эмоции не меняют хитбокс, скорость, урон, дальность взаимодействия, коллизию или положение серверной сущности.
- Анимация — только визуальный слой. Она не должна давать преимущество в PvP или выживании.
- Если анимационный компонент отсутствует или не поддерживает клип, игра продолжает работать без косметической анимации.

## 5. Синхронизация игроков

Сетевой слой должен передавать событие, а не каждый кадр анимации.

Рекомендуемая форма события запуска:

```json
{
  "type": "emote:start",
  "playerId": "server-issued-player-id",
  "emoteId": "losa:greeting",
  "catalogVersion": 1,
  "sequence": 12,
  "startTick": 123456
}
```

Событие остановки:

```json
{
  "type": "emote:stop",
  "playerId": "server-issued-player-id",
  "sequence": 12,
  "reason": "manual"
}
```

Это схема протокола, а не готовая реализация сетевого API. Сервер должен проверять право игрока использовать эмоцию, допустимую частоту запусков и область видимости. Клиент не может сам назначать себе владение VIP-предметами или роли. Для наблюдателей воспроизведение привязывается к серверному времени начала, чтобы анимации не расходились из-за задержки пакетов.

Предлагаемая начальная область видимости — игроки поблизости; точный радиус и формат транспорта определяются при проектировании серверной части. Глобальная рассылка всем игрокам не требуется.

## 6. Разделение платформ

### Java Edition

Нужен отдельный клиентский мод. До выбора целевой версии Minecraft и модлоадера нельзя фиксировать Fabric API, mappings, сигнатуры методов или готовый JAR. Первый технический прототип должен проверить, можно ли безопасно проигрывать пользовательские позы на модели игрока, не вмешиваясь в серверную физику и обычные анимации.

### Bedrock Edition

Нужен отдельный комплект Bedrock-ресурсов. До выбора целевой версии Bedrock требуется проверить доступные механизмы анимации игрока, ограничения Resource Pack / Behavior Pack и необходимость Script API. Нельзя считать, что Java-анимационный код можно перенести напрямую в Bedrock.

### Совместимость каталога

Каждая запись каталога должна иметь платформенные статусы: `planned`, `prototype`, `supported` или `unavailable`. Магазин и инвентарь не должны показывать эмоцию как доступную на платформе, пока соответствующий адаптер не прошёл проверку.

## 7. Владение и безопасность

Каталог описывает эмоции, но не является источником истины о владении. Право использования должно поступать от будущей системы аккаунтов L.o.S.A. В автономном прототипе допускается локальный тестовый флаг, который нельзя выдавать за реальную покупку или серверную проверку.

Не загружать исполняемый код эмоций из пользовательских URL. Ресурсы должны поставляться вместе с проверенным релизом платформенного компонента. Неизвестный ID, несовпадающая версия каталога или некорректные ключи должны безопасно игнорироваться.

## 8. Что входит в этап 1

- общий словарь ID и названий;
- канонический скелет и единицы измерения;
- шесть описаний анимаций и их ключевые кадры в `public/data/emotes-v1.json`;
- правила отмены, воспроизведения и будущей синхронизации;
- явное разделение Java и Bedrock реализаций.

## 9. Что не считается готовым после этапа 1

- проигрывание эмоций внутри Minecraft;
- готовый Java-мод или Bedrock addon;
- колесо выбора, связанное с игровым клиентом;
- сетевой сервер синхронизации;
- реальная проверка владения предметами;
- покупка или выдача эмоций в магазине.

## 10. Следующий технический шаг

После фиксации целевых версий Minecraft отдельно создать Java- и Bedrock-прототипы. Для каждого прототипа проверить полный цикл: запуск эмоции, плавный возврат в idle, отмена движением, корректное отображение на другом клиенте и отсутствие изменения хитбокса/физики.
